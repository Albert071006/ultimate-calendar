# 资料服务运行交接

本文说明后端运行契约和部署操作，不作为某台服务器的部署、真实资料迁移或手机验收记录。`deploy/` 提供需按目标环境核对的 Linux 部署文件。前端与原生桌面接入由各自适配层负责；服务含九项 RPC，以及独立的提炼、推送和 API Key 配置接口。

## 启动与目录

使用 Node.js 24 或更高版本，构建命令为 `npm run build:server` 和 `npm run build:mobile`。产物是 `dist-server/cli.mjs` 和 `dist/`。只运行构建不会启动服务，也不会部署。

`serve` 必须明确提供 `--data-dir` 和 `--origin`。默认监听 `127.0.0.1:3210`，非本机来源必须为 HTTPS；公网或 Tailscale HTTPS 的终止代理应保留规范 Host 和浏览器 Origin，页面、API、Cookie 和 SSE 保持同源。静态目录与私有资料目录不能互为上下级，构造时同时核对真实路径，避免符号链接绕过。

一个资料目录只允许一个服务进程。目录锁属于该服务实例，正常退出后释放；发现活进程时拒绝第二个实例。不可用强制删除数据库、覆盖运行中的 SQLite 或忽略锁来解决启动问题。

Linux 服务数据目录为 0700，服务自身数据库、WAL／SHM、安全备份为 0600，CLI 使用 umask 077。网页目录是只读的构建产物。密钥不放 URL、请求日志、设备响应或安全备份。

## AI 密钥配置与保留

默认启动方式支持手机通过 `/api/v1/ai/config` 管理 Key，完整 HTTP 契约见 `docs/backend-api.md`。CLI 按以下顺序选择唯一供应源：

1. 显式 `--api-key-file <绝对路径>`；文件限制 16 KiB，拒绝符号链接／硬链接、Linux 其他用户权限及不存在／空文件。配置错误停止启动，不回退到其他来源。
2. 非空的 `DEEPSEEK_API_KEY` 环境变量。空值或纯空白视为未设置。
3. 服务资料目录中的 `ai-credentials.json`，由已配对手机管理。没有该文件时以未配置状态启动，普通日历功能仍可用。

前两种为管理员外部配置，API 返回 editable=false，PUT／DELETE 返回 403。要开放手机管理，管理员移除外部配置并正常重启；不会自动把外部 Key 复制到手机管理文件。曾经保存的手机管理配置在使用外部供应源时仍留在原文件，撤去外部配置后会重新读取它，切换后应核对状态。

`ai-credentials.json` 由服务用户拥有，Linux 文件权限 0600，所在资料目录 0700。文件以原子替换方式保存 Key 和随机 revision；这里是**文件权限保护，并非内容加密**。状态、错误响应、会话及正式快照不回传 Key，密钥也不进入业务数据库、通用 RPC 回执或脱敏安全备份。文件损坏或权限不安全时拒绝使用，不静默当成未配置或覆盖旧文件。

保存仅校验格式，不测试供应商有效性或余额；新 AI 工作流动态取值，无需重启，已发出的请求可能继续用旧 Key。清除写入带新 revision 的空配置，保留并发控制信息，不能把文件删除当作普通清除。所有配对设备共享这一配置；应用本身不记录请求 body，反向代理、诊断工具和监控也不得记录此接口的请求内容。

同一资料目录升级会保留该文件，代码包不包含它。安全备份恢复至全新目录后没有 AI Key，需重新配对并由手机填写或由管理员另行配置。不要为“方便恢复”把凭据混进业务备份或发布制品。回滚到不支持手机管理配置的旧版时文件仍保留，但旧版可能不会读取它；恢复新代码后再核对配置，不要删除原文件。

## 资源边界

| 边界 | 默认值与处理 |
| --- | --- |
| 已接收 HTTP 请求 | 全服务 16，同一配对设备 4；超出返回 429 和 Retry-After。SSE 也占用一个请求名额。 |
| HTTP 连接 | 最多 64，单连接最多 100 次请求，空闲 keep-alive 5 秒。 |
| 请求接收 | 请求头 15 秒，整个请求接收 60 秒；普通 RPC JSON 最多 15 MiB，提炼导入 1 MiB，API Key 配置 4 KiB，配对 1 KiB。 |
| 变更流 | 全服务 16、同设备 2；每 20 秒心跳。输出背压时关闭慢连接，客户端重连并重新读取资料。 |
| 并行写工作流 | 全服务 8、同设备 4；超出在创建持久回执前返回 429。已接收的同编号请求继续复用原工作流。 |
| 静态文件 | 使用流式传输，避免每次把资源整份读进内存；私有目录不作为静态目录。 |

HTTP 接收超时不是模型执行时限，模型和排队可能持续更久。代理超时或浏览器断开不代表业务没有提交；RPC 应查询原请求回执，不能生成新编号盲目重放。RPC 的 429／503 可用原编号稍后重试。API Key 配置不写回执、不能进入离线队列；结果不明时 GET 状态并由用户核对，不自动重放。鉴权、版本、身份代际和预览校验不因资源限制放宽。

当前完整快照与账本写回执仍会包含完整正式资料；虽然读取请求已不再永久保存快照回执，大账本每次写入的持久回执仍可能造成近似平方级的累计空间放大。这一轮保持回执语义，尚未实现紧凑回执、分页或多进程横向扩展。监视 `storageBytes.receipts` 和实际内存，部署预算必须先用接近预期规模的虚构资料测量；不要自行删除回执来释放空间或宣称当前资源样例适合无限账目。

## 健康、就绪和备份诊断

| 入口 | 权限与含义 |
| --- | --- |
| `GET /healthz` | 无需配对，仍核对 Host／Origin；只返回进程存活状态。 |
| `GET /readyz` | 无需配对；核对生命周期与轻量数据库查询。排空或存储不可访问返回 503。不是全库完整性或磁盘可写测试。 |
| `GET /api/v1/status` | 需要配对；返回生命周期、活动写请求数、备份时间／状态／失败次数和各自数据库占用字节，不返回路径、密钥或具体资料。 |
| `status --data-dir <绝对目录>` | 本机管理员查看持久备份状态，不创建不存在的资料库；这是最近记录，不代表后台进程仍存活。 |

备份失败不撤销已提交的业务，也不把可读写服务立即摘除。`/readyz` 仍可返回 200，但 `status=degraded`、`checks.backup=failed`；监控必须检查内容。`deploy/check-health.mjs` 对就绪且备份正常返回 0、不可用返回 1、备份降级返回 2，只输出常量诊断码，不输出服务响应或凭据。例如管理员可手动运行：

```sh
node deploy/check-health.mjs --url http://127.0.0.1:3210/readyz --host calendar.example.invalid
```

CLI 会以常量码 `BACKUP_FAILED` 写 stderr；备份状态持久保存到独立运行状态库。启动、写后和定期维护尝试安全备份，后续成功将失败计数与标记清除。备份目录故障应先修复空间、权限或配置，再正常重试；即使业务提示成功，也要处理备份降级。不要把原始异常字符串、请求内容、Cookie 或一次性码加入日志。

## 排空与退出

SIGINT／SIGTERM 触发统一资源关闭：停止接收新业务，关闭 SSE，停止推送调度，等待已接收工作流，最后关闭数据库和释放目录锁。重复退出请求复用同一关闭过程。超过默认 25 秒宽限仍未完成的模型传输会取消；队列中的模型请求不会继续发起网络调用。原回执仍须查询，不能把取消等同于模型供应商未计费。

HTTP 在 30 秒后关闭剩余连接，推送传输会中止，仍等待已接收工作流保存最终状态后才关闭数据库。正常关闭会输出 DRAINING 和 STOPPED；错误使用 SHUTDOWN_FAILED。systemd 样例给出 60 秒停止预算。进程硬崩溃／外部强杀仍由既有 interrupted 恢复规则处理，不作任意崩溃窗口的恰好一次计费承诺。

初始化期间的无效 HTTPS 配置、无法读取显式密钥或其他失败也会清理已打开资源与目录锁，避免同一进程中留下半初始化服务。

## 安全备份与恢复

正式资料使用应用内脱敏 JSON 自动备份，避免将短期手机原文复制到整库备份；仅轮换识别并完整校验通过的自有备份，保留 7 份。账目、余额、归属与关联、任务、课程等正式数据保留；原文、图片、群消息引用、设备会话、VAPID 与 AI 密钥不进入导出。文件仍包含个人正式资料，必须保留私有权限。

`backup` 是离线管理员导出命令，须先正常停止同目录服务。`restore --backup-file <绝对JSON> --data-dir <全新或空目录>` 先严格验证全部格式／关系，再在同级暂存、写入、完整性检查和回读核对，最后移动到目标。目标父目录须已存在，现有非空资料拒绝覆盖；失败只清理本次创建且已验证归属的暂存目录。源备份不变。

恢复生成新资料实例，与旧队列隔离；需重新提供服务端密钥、配对并授权通知。账本审计和更正保留，原账本逐次撤销链不在 JSON 格式中；恢复后新账本操作可撤销。恢复不是 Windows 整库迁移，也不会在后台上传任何个人资料。启用恢复目录前先以合成或已授权资料核对任务关系与余额，再修改服务数据路径。

## 手机静态页面升级与回退

手机前台连接失败后会按退避间隔继续核对会话和资料，隐藏页面停止重连计时，回到前台再恢复。
生活助手在发送前遇到离线会先尝试恢复连接；重连不绕过设备授权、资料身份或代际核对。
已经发送但结果未知的请求仍使用原操作回执核对，不能因网络恢复而生成新的收费请求。

错误中的可选 `delivery` 只描述传输证据：`not-sent` 表示确定没有发送，`unknown` 表示仍须核对原操作；
未提供该字段不能推断未发送。助手会展示真实错误，成功响应后的资料刷新失败也不会把已确认结果改成失败。
紧邻澄清问题的纯文字补充若确定未发送，可恢复为可见草稿供用户继续编辑后发送；
失败请求不会伪装成成功历史，图片、附件和结果未知的请求不自动拼入下一条指令。

先运行 `npm run build:mobile` 生成当前构建的 worker、资源清单及内容摘要，再运行
`node scripts/retain-web-assets.mjs <新静态目录> <当前静态目录> [其他仍需支持的版本目录]`。
它只补充已有指纹资源，不替换首页或 worker；同名资源内容不一致时直接失败。保留资源后不要重新生成离线清单，旧资源仅供尚未关闭的页面按原 URL 请求。

切换静态目录前准备回退目录：复制原静态版本，再向回退目录补充新版本指纹资源。
这样升级或回退时，已经拿到 HTML、尚未下载脚本的页面都能继续打开。
原子切换目录指针后检查当前首页、worker 和新旧指纹资源；静态更新不需要重启资料服务。

使用两份实际构建产物执行
`node scripts/smoke-mobile-upgrade.mjs <原静态目录> <新静态目录>`，验证升级、缓存重开、缺失资源、慢会话、回退和同源恢复入口。
该脚本使用独立的 Microsoft Edge 测试目录和虚构资料，不连接生产服务。浏览器测试耗时不代表 iPhone 实机耗时。
出现错误时恢复入口仅重新载入同源页面，不清除 IndexedDB、配对 Cookie 或待提交队列。

## Linux 部署样例的审阅与验证

`deploy/ultimate-calendar.service` 使用独立用户、只读代码目录和 systemd 私有状态目录。默认由手机管理 Key，也可使用可选的 root-owned 0600 `/etc/ultimate-calendar/secrets.env` 供应 `DEEPSEEK_API_KEY`；选择后者会锁定手机配置写入。`deploy/server.env.example` 只放占位来源和可选推送联系地址。若另行改为 `LoadCredential`，需按目标 systemd 版本验证支持，并由管理员提供可读的私有文件和对应 `--api-key-file` 参数。不得把真实密钥写回示例。

`deploy/nginx.conf.example` 只代理回环后端，关闭缓存、请求重试和 SSE 响应缓冲，保留来源与 Cookie；域名和证书路径均为不可直接使用的占位值。若选择 Tailscale Serve，应在资料服务所在机器建立私人 HTTPS 入口，保留日历设备配对；不自动启用 Funnel，不让 Windows 采集电脑变成必经中转点。

目标 Linux 上由管理员先确认 Node 24 路径、服务用户、证书、磁盘权限、内存预算以及出站 DeepSeek／推送访问，再运行 `systemd-analyze verify` 与选用 NGINX 时的 `nginx -t` 等目标平台检查；本机 Windows 测试不代替它们。当前 unit 的 512 MiB V8 堆、768 MiB 内存软预算和 1024 MiB 硬上限只是起点，需按虚构数据负载调整。不要启用会阻断 V8 JIT 的执行内存策略而不做实测。

相关自动化检查覆盖匿名探针不泄露资料、鉴权状态接口、备份失败与成功恢复、HTTP／SSE 过载、写工作流准入、排空中拒绝新请求、等待已接受操作、超时取消模型、部分启动失败资源清理、幂等关闭及新目录安全恢复。具体版本的执行结果与目标 Linux 部署状态应分别记录，不能由本文推断某台服务已经验收。

## Windows 采集专用后端

`src/electron/collector-mode.ts` 导出 `startCollectorMode(directory)`，供明确选择 `--planner-capture-only` 的主进程入口使用；主进程继续负责单实例锁、与远程界面模式互斥、托盘和退出确认。该入口只接受既有普通 `planner.sqlite`，缺失时拒绝，不创建空来源库、不做 AppData 猜测或资料迁移。本轮未在用户实际环境切换模式或连接真实 QQ。

模块复用原本机 Repository、CaptureStore、CaptureService、文档解析、模型队列和 safeStorage 凭据。沿用 `credentials/deepseek.bin`、`credentials/qq-bridge.bin` 以及既有采集开关／群选择／端点；不重填密钥、不清空配置、不启动或修改 QQ／QQ-agent。凭据加载失败只报常量告警并保留原文件，需要时正常退出后重试，不自动覆盖有效配置。

此模式不构造 PlannerService、Controller 或 LedgerService，没有本地正式编辑界面，也不生成账本月津贴；本机库继续作为原始采集与提炼的私有来源。提炼仍沿用本机已有 DeepSeek 配置和费用规则；投递到资料服务须另接严格白名单提炼桥，采集已连接不等于云端已经收到结果。没有新增采集配置 UI，切换前应核对已有设置。

返回的 `status()` 只有 connection、error 布尔、enabled、analysisEnabled，可用于托盘表明断连／停用；不会返回账号、群、消息或原始错误字符串。`close()` 先 stop 采集、dispose 文档处理，随后等待采集 busy 与模型队列都闲置，再关闭 CaptureStore 和 Repository。停止或文档取消失败会保留数据库并明确拒绝本次退出，允许再次重试；不会假装已经安全关闭。超过 25 秒可取消模型传输，但不能提前关掉仍有批次回调的数据库；在途附件遵循原最多 60 秒下载限时，退出入口必须 await close，不应强杀或直接替换数据库。

合成 DI 单测覆盖缺库拒绝、凭据／配置复用、脱敏状态、busy 等待、启动失败清理与宽限后的模型取消，没有真实桥接请求或付费 AI 调用。
