# QQ 通知的事项归并

提炼单位是可独立判断、完成的事项。通知中的步骤、材料要求、照片格式和地点限制应归入同一候选，不按编号逐条建立待办。群成员、组长和工作人员的职责分别理解，没有用户身份依据时不分配组织者职责。

## 正文、附件与分片

- 同一事项的正文、图片、表格和附件可以共同支持一张待判断卡。每份补充来源须引用当前请求中的真实分片及其中原文，保存后仍能逐一查看各自的发送时间、正文和附件入口。
- 主来源保留 `sourceIds` 与 `sourceQuote`；附加依据使用可选的 `supportingSources: [{ sourceId, quote }]`。时间字段仍须由主来源的时间证据支持，不能把另一条消息的日期借过来推算。
- 同一次响应若分别提炼了同一事项，可用相同的可选 `eventKey` 表明归属。它只在这次响应内有效，不作为跨群或跨批次的永久事件编号。独立事项使用不同标识；时间或地点冲突继续交给用户判断。
- 大文件需要多次请求时，后续请求会看到前面已完成分片的候选摘要和稳定暂存编号，可以关联补充或重复内容；最终保存时再把暂存编号解析到正式候选。暂存结果不提前变成可操作卡片。
- 同标题不等于同一事项。没有明确归属时保持独立；其他人的定向通知不能通过补充来源绕过收件人过滤。

## 后续补充

- 新批次提供同账号、同群的候选摘要，以及批次发送时间之前 24 小时内至多 20 条正文（最多 8000 字）。前文只辅助理解，不能代替当前原文的时间证据。
- `supplement` 表示追加信息：未处理候选原位增补，保留未再次提及的时间、条件与来源。明确相互矛盾的时间、地点转为关联变更。
- 明确关联已有候选的 `duplicate` 也按同一套受保护的补充规则处理，不因标题或行动措辞不同而另建无关卡片；关系不确定时仍留待核对。
- 已接受的任务和日历安排不会自动改变。变更候选由用户判断；已忽略的事项不因补充重新进入待判断。
- 不同群不以相似标题关联。相同群的不同活动也不能仅因关键词或时间相近合并。
- 已付费分片保留原 checkpoint，更新分析规则不重放已完成请求。中断续跑会从保存的响应重建暂存编号与上下文，跳过已完成请求；重复提交仍由原批次回执拦截。新字段均可省略，旧响应继续可读，不自动重算旧批次或追溯改写用户决定。

## 云端同步

新采集桥携带可选的 `eventId`、`eventRevision` 与 `legacyDistilledIds`。标识为不可直接识别本机路径、账号、群或来源的摘要；具体消息关联仍在本机私有索引中。

旧内容摘要用于定位已经同步的卡片。相同事件的后续版本更新同一待判断卡片；采用前次导入值、当前值、新值的比较，保留用户手工编辑和稍后处理状态。已接受的事项只生成关联变更候选，已忽略或删除的卡片不复活。旧客户端回执仍有效，旧版本重放不会覆盖新版本。

服务端需先升级，再启用新采集桥。此功能不上传 QQ 原文、附件或本机资源路径，也不控制 QQ 客户端。
