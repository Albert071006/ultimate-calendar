## 终极日历本地版 0.8.1

下载 `UltimateCalendar-Local-Setup-0.8.1.exe` 在 Windows x64 使用。日历、课表、任务、目标和账本保存在自己的电脑上，无需部署日历服务器；手动功能无需 API Key。AI 由本机直接调用自己的 DeepSeek API，需要联网并由自己的 API 账户承担费用。本地版只有桌面端，没有手机端或跨设备同步。

### 今天待办按时间排列

「今天」列表同时考虑任务截止时间、已安排时段和通知中的活动时间，按「已过时间、今天、本周、以后、时间未定」分组，同组内按时间先后排列。没有截止日期但有集合、会议等活动时间的待安排任务，也会出现在对应位置。仅调整列表显示，不自动安排时段或修改截止时间。

### 通知正文优先提炼

- QQ、微信采集的合批等待缩短为 15 秒，从首条消息导入起计算，后续消息不会持续推迟处理。15 秒是合批等待，不是从消息发出到显示结果的总时长；仍取决于采集进程、附件准备、排队和 AI 响应。
- 进入 AI 分析后，优先处理通知正文，再补充附件。连续的 DOCX 正文段落合并送入模型，减少长文档产生的大量小分片；原文和附件仍完整保留。
- 长附件每完成一轮新请求就让其他批次有机会处理，避免持续占用分析队列。
- 保留旧批次的分片进度及已保存回答。重试时先核对和应用原回答，已完成部分不因这次升级重新请求；结果未知的失败仍暂停等待核对。
- 修复来源较多的附件补充无法保存的问题。超过单个事项的来源上限时，保存为关联原事项的待判断补充，保留全部来源和用户已有决定。

### 升级与下载核对

升级前备份并正常退出应用，保留资料和有效凭据。新生成的采集检查点包含新版分析规则，回退前须核对进行中批次与程序版本；不要通过清空采集库或重新分析整批解决升级问题。0.8.0 的思考设置及此前借款、自定义账户兼容限制仍适用。

本地版继续使用独立安装身份、`local.yml` 更新通道与「文档/终极日历本地版」资料目录，不自动导入标准版或云端资料。QQ、微信采集需另行配置，见[本地版指南](https://github.com/Albert071006/ultimate-calendar/blob/v0.8.1/docs/local-desktop.md)。安装包未购买代码签名证书，请核对同一 Release 的 `SHA256SUMS-local.txt`。

需要手机和电脑共用资料时，选择单独发布的[服务器版与手机端 0.8.1](https://github.com/Albert071006/ultimate-calendar/releases/tag/server-v0.8.1)，自行部署常在线服务器。
