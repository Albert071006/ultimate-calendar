## 服务器版与手机端 0.10.0

需要自行部署并维护常在线的 Linux 云服务器，配置 Node.js 24、域名和 HTTPS。服务器保存资料并调用自己的 DeepSeek API；手机通过网页/PWA 使用，Windows 标准版连接同一服务。项目不提供公共托管账号。

### 操作提速与后台备份

- 日历、任务及设置的普通写入返回本次变化，电脑和手机按增量更新；断档、恢复或资料实例变化时重新读取完整快照。保留原操作编号和回执核验，不把排队或连接恢复视为保存成功。
- 云端修改先提交数据库，从首次尚未备份的修改起约一分钟合并生成后台安全备份，保留最近 7 份有效自动备份。独立 worker 在同一读取事务中取得日历和账本，校验新文件后原子发布；未变化的旧文件复用校验结果。
- 桌面“数据与备份”和手机设备页显示备份进度及最近成功时间。失败保留待备份状态并重试，恢复前保护备份与正常退出收尾仍保留。本机采集原文的完整自动备份继续每天一次，改为后台执行。

### AI 输入与采集

生活助手的记账分流减少无关日历资料，稳定规则前置；日历引用和群通知采用紧凑表示，重复正文只携带一次。记账保留最新索引和相关详情，修改旧账、退款或 AA 关联前补齐必要原记录。采集按来源补读证据，按内容和解析版本复用附件提取结果；缺失或改变的证据保留待核对。实际输入量及缓存命中率依赖内容、补读和服务商缓存，不承诺固定比例。

修复 QQ、微信因短暂云端密钥同步失败而持续暂停分析的问题：同步恢复且有效配置已确认后，可恢复可核实的误暂停；手动暂停、真正鉴权失败及结果未知请求保留原保护。微信附件明确区分缩略图、未下载及密钥问题；仅有日期的活动保留暂定时间，不补造时分。

### 下载与升级

- `UltimateCalendar-Setup-0.10.0.exe`：Windows 标准版客户端，附同次构建的更新元数据、blockmap 和校验文件。
- `UltimateCalendar-Server-Mobile-0.10.0.tar.gz`：已构建的后端、后台备份 worker、手机网页/PWA、systemd 配置、NGINX 示例及部署说明，目标服务器无需运行 `npm ci`。
- `SHA256SUMS-server.txt`：服务器部署包校验文件。

协调更新后端、Windows 标准版及手机页面。保存草稿并正常退出 Windows 程序；服务端先正常停止并保留更新前备份、持久资料目录及配对凭据，再切换程序。**部署必须包含与 `cli.mjs` 同次构建的 `backup-worker.cjs`，不能只复制主入口文件。** 手机静态目录需保留旧页面引用的指纹资源，升级不要求清缓存或重新配对。

本版新增持久增量记录、能力协商和采集检查点字段。旧客户端仍可使用兼容响应；回退旧后端或采集程序前需核对新操作回执、检查点与资料兼容性，不用恢复旧数据库代替程序回退。手动“记一笔”保持纯手动，升级不补账、不重分类已有流水。

部署步骤见[服务器与手机指南](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.10.0/docs/server-mobile-deployment.md)及[运行与备份说明](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.10.0/docs/backend-operations.md)。发布下载包不代表已替使用者部署服务器。

无需服务器、仅在一台 Windows 电脑使用时，选择[纯本地桌面版 0.10.0](https://github.com/Albert071006/ultimate-calendar/releases/tag/v0.10.0)。两版的安装身份、资料目录与更新通道继续分开。
