## 服务器版与手机端 0.6.0

本 Release 供手机与 Windows 电脑共用一份日历、任务和账本。使用者需要自行部署并维护一台常在线的 Linux 服务器，配置 Node.js 24、域名与 HTTPS。服务器保存资料并调用自己的 DeepSeek API，手机通过网页/PWA 使用，Windows 标准版可连接同一服务。项目不提供公共托管账号。

### 下载内容

- `UltimateCalendar-Server-Mobile-0.6.0.tar.gz`：已构建的 Node 后端、手机网页/PWA、systemd 配置、NGINX 示例和部署说明。目标服务器无需运行 `npm ci`。
- `SHA256SUMS-server.txt`：服务器部署包校验文件。
- `UltimateCalendar-Setup-0.6.0.exe`：可选 Windows 标准版客户端，另附同次构建的更新元数据、blockmap 和校验文件。

首次部署见[Linux 部署与手机使用指南](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.6.0/docs/server-mobile-deployment.md)。每台手机或电脑分别使用服务器生成的一次性码配对；没有 API Key 时仍可手动管理资料。电脑关机不影响持续在线服务器上的资料读写，但新的本机 QQ、微信采集会暂停。

### 本次更新

- 普通任务默认单时段，完成或恢复时段时同步任务状态；需要分次执行时明确勾选「安排多个时段」。手机在日历事项的「编辑时段」中也能直接设置，已有多段及重复安排保留。
- 按消息发送日期解析「今天」「明天」等相对日期，避免不同日期的同名通知混为一个事项；已处理通知按显示时间从新到旧排列。
- 改善手机首屏启动、断网重连、会话恢复以及 PWA 升级和回退，保留配对、缓存与待提交队列。未提交的离线草稿不等于服务器已保存。
- 生活助手显示实际连接错误；确定未发送的澄清文字可恢复为可见草稿，结果未知的请求先核对原回执，不自动重复发起 AI 请求。
- Windows 标准版新增微信只读选群采集，支持本机已同步消息及已缓存、下载的图片和文件，复用现有解析、AI 提炼与待判断流程。未就绪附件单独等待并自动复查，不阻塞其他消息。

### 微信配置与升级

**微信采集需在 Windows 另行配置 Python 运行时和依赖；部分 HEVC 图片需单独安装 FFmpeg。** 日历安装包不含这些组件或微信客户端，请按[微信配置指南](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.6.0/docs/wechat-capture.md)设置。采集默认关闭；它不代替微信下载、发送消息或读取完整云端历史，语音、视频和压缩包不做内容分析。微信兼容性取决于客户端版本，图片识别取决于所选模型能力。

QQ、微信的原文、附件与提炼均留在采集电脑，可通过独立摘要桥将提炼结果送到服务器；手机和 Linux 服务器不会直接登录微信或 QQ。AI 分析所需内容仍会发送给用户所配置的模型服务。

升级前核对归档摘要并备份；保留服务器资料、凭据、配对和环境配置。手机静态升级必须保留旧页面引用的指纹资源，并准备包含新资源的回退目录，避免主屏幕缓存加载旧脚本时遇到 404；具体见[部署指南的升级步骤](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.6.0/docs/server-mobile-deployment.md#7-备份升级与恢复)。不需要清空手机资料或重新填写有效 Key。

本 Release 与[纯本地桌面版 0.6.0](https://github.com/Albert071006/ultimate-calendar/releases/tag/v0.6.0) 分开发布。两种桌面版的安装身份、资料目录和更新通道保持独立。发布包不包含私人资料或凭据，构建验证不代表已替使用者部署并验收其服务器或手机。
