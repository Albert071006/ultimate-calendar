## 服务器版与手机端 0.7.0

本 Release 供手机与 Windows 电脑共用一份日历、任务和账本。使用者需要自行部署并维护一台常在线的 Linux 云服务器，配置 Node.js 24、域名与 HTTPS。服务器保存资料并调用自己的 DeepSeek API，手机通过网页/PWA 使用，Windows 标准版可连接同一服务。项目不提供公共托管账号。

### 下载内容

- `UltimateCalendar-Server-Mobile-0.7.0.tar.gz`：已构建的 Node 后端、手机网页/PWA、systemd 配置、NGINX 示例和部署说明。目标服务器无需运行 `npm ci`。
- `SHA256SUMS-server.txt`：服务器部署包校验文件。
- `UltimateCalendar-Setup-0.7.0.exe`：可选 Windows 标准版客户端，另附同次构建的更新元数据、blockmap 和校验文件。

首次部署见[Linux 部署与手机使用指南](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.7.0/docs/server-mobile-deployment.md)。每台设备用服务器生成的一次性码配对；没有 API Key 时仍可手动管理资料。服务器在线时，Windows 电脑关机不影响手机读写，但新的本机 QQ、微信采集会暂停。

### 电脑与手机共同新增

- **借款往来**：支持借入、借出、归还借款和收回借款。本金只影响资金与借款余额，不计普通收入、资产变现或个人开销；利息、手续费单独记录。归还或收回可关联对应原借款，支持部分、跨月结清，显示每笔本金、已还收、剩余及总待还、待收，与 AA / 代垫分开统计。无原借款时保留未关联和剩余未知，不猜测抵扣。
- **独立账户**：在「账单 → 账户」新增现金或储值账户，编辑名称和别名；银行多卡可加尾号，不同店铺会员卡分别管理。支付、转账、借款、余额、筛选、明细和固定生活费规则都使用共享账户目录。新账户余额未知，不虚构初始余额，也不自动修改历史流水的归属。
- **账户识别**：生活助手可依据用户明确提供的银行、店铺名称建立独立账户；遇到多卡或名称含糊时要求核对，避免把不同账户合并。
- **助手错误与重试**：区分空响应、截断、无效 JSON 和字段不符合约定，显示脱敏诊断标识。确定模型结果未采用时可主动「重新分析」，会再次调用自己的 API；已保存或处理结果未知的请求先核对回执。交易校验拒绝显示具体原因，避免重放被拒绝的原提案或重复记账。

原有「其他还款（信用卡等）」保持原义，不自动转换旧记录；本版仍不提供完整的信用卡负债管理。QQ、微信采集配置与附件能力沿用 0.6.0，详见[微信配置指南](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.7.0/docs/wechat-capture.md)。采集在 Windows 电脑运行，手机和 Linux 服务端不会直接登录 QQ 或微信。

### 必须协调升级，保留资料

**新增借款和自定义账户数据不受旧版支持。** 升级前备份服务器资料并校验部署包；保留数据、凭据、设备配对和环境配置。正常停止服务后更新后端与手机静态资源，同时更新连接此服务的 Windows 标准版至 0.7.0。手机关闭旧页面后重新打开或刷新，确保加载新版；旧客户端会提示升级，不能继续使用旧账本界面。

手机静态部署须保留旧页面引用的指纹资源，避免缓存中的页面请求旧脚本时遇到 404，见[升级步骤](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.7.0/docs/server-mobile-deployment.md#7-备份升级与恢复)。保留资源只解决页面加载兼容，不能让旧程序读取新的账本格式。使用新数据后，不要仅切回旧后端或旧桌面程序；恢复须先确认数据与版本兼容，并保护升级后的新增记录。不要清空手机资料、删除数据库或重新填写仍有效的 Key 来处理升级提示。

本 Release 与[纯本地桌面版 0.7.0](https://github.com/Albert071006/ultimate-calendar/releases/tag/v0.7.0) 分开发布。本地版无需日历服务器，由电脑直连自己的 API，且没有手机端。两种桌面版继续使用独立安装身份、资料目录和更新通道。构建验证不代表已替使用者部署并验收其服务器或手机。
