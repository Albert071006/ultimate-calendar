## 服务器版与手机端 0.8.1

本 Release 供手机与 Windows 电脑共用一份日历、任务和账本。使用者需要自行部署并维护一台常在线的 Linux 云服务器，配置 Node.js 24、域名与 HTTPS。服务器保存资料并调用自己的 DeepSeek API，手机通过网页/PWA 使用，Windows 标准版可连接同一服务。项目不提供公共托管账号。

### 下载内容

- `UltimateCalendar-Server-Mobile-0.8.1.tar.gz`：已构建的 Node 后端、手机网页/PWA、systemd 配置、NGINX 示例和部署说明，目标服务器无需运行 `npm ci`。
- `SHA256SUMS-server.txt`：服务器部署包校验文件。
- `UltimateCalendar-Setup-0.8.1.exe`：可选 Windows 标准版客户端，另附同次构建的更新元数据、blockmap 和校验文件。

首次部署见[Linux 部署与手机使用指南](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.8.1/docs/server-mobile-deployment.md)。每台设备用服务器生成的一次性码配对；没有 API Key 时仍可手动管理资料。服务器在线时，Windows 电脑关机不影响手机读写，但新的本机 QQ、微信采集会暂停。

### 本次更新

- **电脑和手机的今天列表**：结合截止时间、已安排时段和通知活动时间，按已过时间、今天、本周、以后和时间未定分组，同组内按时间排序。没有截止日期的待安排活动也能按实际活动时间排列，不改任务内容或安排。
- **本机采集提速**：QQ、微信消息从首条导入起等待 15 秒合批，后续消息不再推迟合批。进入 AI 分析后优先处理通知正文，再补充附件；连续 DOCX 正文段落合并，长附件每轮请求后让其他批次有机会处理。总延迟仍取决于采集、附件准备、排队、AI 和同步，不承诺 15 秒内出结果。
- **分析恢复与来源保留**：旧批次继续使用原检查点，已保存回答优先恢复，已完成部分不重复请求。大量来源超过单个事项上限时保存为关联补充，保留原文与用户已有决定；结果未知的失败仍需核对。
- **更及时的摘要发送配置**：补充常驻发送桥的 10 秒轮询示例和计划任务说明。已有自建部署需要按[发送桥指南](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.8.1/docs/qq-cloud-bridge.md#减少摘要发送等待)配置；安装包不会自动修改现有计划任务。发送桥不调用 AI，页面自身刷新和网络仍可能增加显示等待。

QQ、微信采集及原文附件仍在 Windows 电脑上，手机和 Linux 服务端不直接登录 QQ 或微信。本版不会自动重写历史通知、账目或备份，也不会替用户接受待判断事项。

### 升级并保留资料

升级前备份并校验部署包。按部署指南更新服务器包和手机静态资源，正常退出后更新 Windows 标准版至 0.8.1；保留资料、凭据、设备配对和环境配置。手机关闭旧页面后重新打开或刷新，无需清空资料或重填有效 Key。手机排序需要新的静态资源，采集提速需要新的 Windows 采集程序；发布下载包不代表已经替使用者部署服务器。

新生成的采集检查点包含新版分析规则，回退前须核对进行中批次与程序版本。0.8.0 的思考设置及此前借款、自定义账户兼容限制仍适用。手机静态部署须保留旧页面引用的指纹资源，见[升级步骤](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.8.1/docs/server-mobile-deployment.md#7-备份升级与恢复)；恢复或替换本机采集数据库前，还应正常停止持有只读连接的摘要发送桥。

本 Release 与[纯本地桌面版 0.8.1](https://github.com/Albert071006/ultimate-calendar/releases/tag/v0.8.1) 分开发布。本地版无需日历服务器，由电脑直连自己的 API，没有手机端。两种桌面版继续使用独立安装身份、资料目录和更新通道。
