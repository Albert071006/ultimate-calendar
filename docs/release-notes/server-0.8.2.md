## 服务器版与手机端 0.8.2

本 Release 供手机与 Windows 电脑共用一份日历、任务和账本。使用者需要自行部署并维护一台常在线的 Linux 云服务器，配置 Node.js 24、域名与 HTTPS。服务器保存资料并调用自己的 DeepSeek API，手机通过网页/PWA 使用，Windows 标准版可连接同一服务。项目不提供公共托管账号。

### 下载内容

- `UltimateCalendar-Server-Mobile-0.8.2.tar.gz`：已构建的 Node 后端、手机网页/PWA、systemd 配置、NGINX 示例和部署说明，目标服务器无需运行 `npm ci`。
- `SHA256SUMS-server.txt`：服务器部署包校验文件。
- `UltimateCalendar-Setup-0.8.2.exe`：可选 Windows 标准版客户端，另附同次构建的更新元数据、blockmap 和校验文件。

首次部署见[Linux 部署与手机使用指南](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.8.2/docs/server-mobile-deployment.md)。每台设备用服务器生成的一次性码配对；没有 API Key 时仍可手动管理资料。服务器在线时，Windows 电脑关机不影响手机读写，但新的本机 QQ、微信采集会暂停。

### 本次更新

- **固定生活费后台检查**：启用并保存规则后，常驻服务器在启动及每 30 秒空闲时检查已到月份，不再依赖手机或电脑打开账单。繁忙时延后，不保证每月 1 日 00:00:00 精确执行；停机后在服务恢复时检查。已有、撤销或作废月份不重记，暂停期间不补记，不提前生成未来月份。到账账户按保存的规则处理，未指定时保留待确认；不向支付平台核验真实到账，不随升级自动启用或改写规则。
- **API 缓存优化**：助手将稳定资料前置，动态时间、页面等后置；Windows QQ、微信提炼的固定提示不再嵌入每批来源 ID。保留最新账本、严格来源校验、防重复保护和旧分析检查点。实际缓存命中率须看升级后的正常请求，不承诺固定比例，历史统计不会改变。
- **AA 返款修复**：原消费全额计入个人开销且能唯一明确关联时，同一事务更正原个人承担并记录返款到账，不重复算收入或消费；已按净额登记的原消费不重复冲减，歧义、重复及超额情况继续保留核对保护。
- **亲情卡归还借款**：手机、电脑手工录入和生活助手均支持登记已发生的亲情卡归还本金。计入亲情卡已使用额，不计普通收入或个人开销，不扣现金余额、不推算真实剩余额度；原借款关联、分次结清及超额保护保留。
- **管理命令隔离**：CLI 备份和资料代际更新不启动生活费调度，避免维护命令触发新的自动记账。

QQ、微信采集及原文附件仍在 Windows 电脑上，手机和 Linux 服务端不直接登录 QQ 或微信。升级不会自动重试此前失败的记账指令或重放已完成交易。

### 升级并保留资料

升级前备份并校验部署包。按部署指南更新服务器包和手机静态资源，正常退出后更新 Windows 标准版至 0.8.2；保留资料、凭据、设备配对和环境配置。手机关闭旧页面后重新打开或刷新，无需清空资料或重填有效 Key。生活费调度、助手缓存及记账修复需要新版后端；手机手工还款需新版页面，群消息缓存优化需新版 Windows 采集程序。发布下载包不代表已经替使用者部署服务器。

**写入亲情卡归还借款记录后，不可直接回退到不支持该记录的旧后端或桌面程序。** 回退前须检查现有账本、历史及待核对操作的兼容性，保留升级后新增资料，不能用旧数据库覆盖。此前思考设置、自定义账户和采集检查点的兼容要求仍适用。手机静态部署须保留旧页面引用的指纹资源，见[升级步骤](https://github.com/Albert071006/ultimate-calendar/blob/server-v0.8.2/docs/server-mobile-deployment.md#7-备份升级与恢复)；恢复或替换本机采集数据库前，还应正常停止持有只读连接的摘要发送桥。

本 Release 与[纯本地桌面版 0.8.2](https://github.com/Albert071006/ultimate-calendar/releases/tag/v0.8.2) 分开发布。本地版无需日历服务器，由电脑直连自己的 API，没有手机端。两种桌面版继续使用独立安装身份、资料目录和更新通道。
