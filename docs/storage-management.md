# 空间管理

入口：我的 → 数据与备份 → 空间管理。自动备份、更新／恢复前备份和手动导出的默认位置统一为系统“文档”目录下的 `终极日历/备份`，当前路径显示在空间管理页。正式数据位于同级 `终极日历/数据`，与备份分开。规则和备份位置保存在 `space-management.json`，不包含密钥。隔离测试配置始终使用自己的资料和 `backups` 目录。

## 固定资料位置

Windows 打包应用启动的子进程可能将 AppData 重定向到包私有目录，同一个表面路径因此可能对应不同数据库。生产版在申请单实例锁之前把资料目录固定到系统“文档”目录下的 `终极日历/数据`；普通桌面启动与代理启动使用同一份数据库和凭据。显式 `--planner-profile` 继续使用指定的隔离目录。

旧 AppData 数据仅作为首次迁移来源；迁移使用 SQLite 备份接口并保留原库。新位置建立后不再反复选择旧库。不要在应用运行中替换数据库文件，也不要仅复制主文件而遗漏 WAL 中的修改。

## 默认规则

| 类别 | 默认策略 |
|---|---|
| 自动清理 | 开启；启动后约一分钟检查，运行期间每小时空闲执行，忙时延后 |
| 自动备份 | 最多保留 7 份 |
| 更新／恢复前备份 | 最多保留 3 份 |
| 受管理备份 | 合计目标 2048 MiB；必要的最新有效备份优先保留 |
| 已处理 QQ 附件 | 保留 30 天，容量目标 1024 MiB，超额从最旧可清批次开始 |
| 界面缓存 | 手动清理时可勾选；使用 Electron 清理接口 |

备份容量目标只适用于程序能明确识别的 `auto-时间-UUID.sqlite`、`before-update-UUID.sqlite`、`before-restore-UUID.sqlite`。每类最新备份通过完整性和结构校验后才轮换；至少保留每类最新有效备份。最新备份校验失败时暂停该类清理。含 WAL/SHM 的备份、未知文件、子目录、链接、手工导出和旧排障资料不自动删除。

## 数据保护

- 不删除账单、任务、课表、目标、候选事项、消息正文、已提炼结果和操作历史。
- 尚未完成分析、待判断、未完成任务或未来活动依赖的附件保留。共享附件只有最后一个引用被清理时才删除内容。
- 按最后导入／处理时间计算保留期限，避免刚补采的旧消息因发送日期太早立即过期。
- 清理附件会删除附件内容、解析分片和重复的模型输入；保留批次处理结果。已清理附件不能再次查看或分析。
- 容量是目标而非硬上限：受保护资料超额时显示原因，不强制删除。
- 不处理 QQ 客户端自身的文件，不停止或重启 QQ。

清理后由 SQLite 原地压缩可回收空间，不在打开连接时替换数据库文件。少量空闲页保留复用；空间不足或数据库忙时延后压缩。

## 大备份

备份与恢复不再限制为 512 MiB。QQ 附件逐条校验和复制，不再把全部附件转成 base64 同时载入内存。备份、恢复暂存、安全备份和恢复写入均检查磁盘可用空间；现有单附件处理上限保持不变。

恢复预览保留独立暂存文件和只读连接，十分钟过期；再次预览、恢复完成或正常退出会清理暂存文件。恢复仍使用单个事务，同时检查期间是否出现新修改，失败时回滚。恢复前安全备份和密钥保留。
